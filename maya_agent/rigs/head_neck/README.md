# 头部 / 颈部 v1.1.0

依据用户 Maya 参考场景的 `main1 / null3 / neck_ctr1` 和 `Head_ctr1` 关系重新构建。集成 v1.4.1 的头脖子部位使用本模块，不再复用脊柱系统；身体绑定保持原模块。

v1.1.0 修正 v1.0.0 的运动差异：点约束的 maintainOffset 是固定空间偏移，不能代替父级旋转带来的骨骼端点位移。新版用父级下的锚点携带偏移，再用无偏移点约束读取锚点世界位置。控制器也改为统一角色坐标朝向，使用独立输出偏移匹配骨骼轴向，避免直接混合不同骨骼朝向。

按颈根 → 其余颈骨 → 头载入 2–64 个目标。单颈与参考一致；多颈扩展为沿链的位置跟随及递增的头部方向权重。所有运行数据和逻辑在包内，不导入参考 Maya 文件或 outputs，不需要原插件、回调或脚本节点。

## 节点关系

- 头是 locator 控制器 `Head_ctr1`；颈部是 joint 控制器 `neck_ctr1…`。
- 每根颈部控制器单独放在 `neckXX_blend` 组下；所有这些组与头控制器位于同一个独立 `rig_root`。
- 第一根颈骨位置读取胸部下的 `neck01_anchor`；后续颈骨读取前一个颈部控制器下的对应锚点。锚点跟随父级旋转、平移，点约束自身 offset 为零。
- 所有控制器共用角色坐标框架；Y-up 时组旋转 X=-90°，对应参考 `main1`。`chest_orientation` 将身体控制器的绑定朝向归一到此框架。`output_frame*` 保存控制器与骨骼的绑定轴向差异，驱动原目标。
- 颈部方向组使用胸与头两个 orientConstraint 目标。单颈各占 0.5；多颈的头权重为 `(index+1)/target_count`。控制器自身旋转可在混合方向上继续编辑。
- 头部旋转独立；头部位置读取最后一根颈部控制器下的 `head_anchor`。因此旋转脖子时头部位置沿真实骨骼长度绕颈根移动。位置连接到头自身的 translate，不能放入头父矩阵，否则会与颈部方向混合形成求值循环。
- 未载入身体时，颈根参考使用通用根；也没有通用根则使用本地固定参考。
- 多空间开关启用时，头部 `global=0` 保留独立方向，`global=1` 跟随胸部方向；位置仍沿颈骨链跟随。双目标权重明确，不复刻参考文件单目标零权重的不确定行为。

头部平移由点约束驱动。若需要额外平移，可编辑 `positionOffsetX/Y/Z`；动画转移时它们保存原目标与跟随链之间的平移差。颈部 TR、头部旋转仍是普通可编辑动画通道。

## 动画

内部入口 `build(item, targets, namespace, chest=None)` 由集成 builder 在捕获原始世界动画后调用。先求头部旋转，再求颈部链的局部 TR，最后求头部平移补偿，避免逐帧误差累积。源 TR 动画的备份、交接、蒙皮和父级保护由集成构建器统一管理。只保证用户指定范围的采样帧。

构建输出为 Maya 原生变换、joint、locator、orientConstraint、pointConstraint 和 plusMinusAverage；不保留临时源读取约束，也不从已经被新绑定驱动的原目标反读姿态。

验证见 `scripts/test_head_reference_behavior_live.py`：从当前参考记录的控制器与骨骼姿态建立临时参考约束链，分别改变胸、头、颈的 XYZ 旋转及组合旋转，与生成系统的骨骼世界矩阵逐项比较。旧版本可重现最高约 10.8 的误差；新版容差 1e-4。它不会编辑源参考控制器。

`scripts/test_reference_hierarchy_live.py` 与 `scripts/test_reference_character_copy_live.py` 另覆盖动画拷贝、多节颈部、多空间、通用根、手臂对齐及实际参考角色姿态。
